## 4 充值与积分账本

### 4.1 已确认业务规则

F03：普通充值提供1、10、50、100元快捷档位，支持自定义整数金额。用户点击“我已付款”，可选上传付款截图。普通充值1元兑换10积分。订单从创建起满2小时，未声明付款则自动关闭；已点击“我已付款”则转待核查并暂停自动关闭，由人工确认。单笔不足200元由客服核销，200元及以上由管理员审核，审核通过后系统自动入账；财务负责对账。

优惠积分包后台可保存多档，前台同时最多展示5档，价格、积分数量和有效期可配置，从核销成功、积分到账时起算。用户举例为“5元购买有效期1年的100积分”，这是可配置示例，不是全站固定售价。普通直接充值积分永久有效；优惠积分按批次设置有效期。此补充规则优先于第二轮前文笼统的“不同批次有效期”。

F04：软件与资源一次兑换扣积分，API按周期或调用量扣积分。消费先扣最早到期的积分，最后扣永久积分。客服根据交付、使用情况及问题原因逐单审核退款并记录理由；退款退回原批次及原有效期，已过期部分从退款到账时起有效30天。尚未确认人民币提现或原路退钱能力。

### 4.2 模拟充值与真实充值隔离建议

充值记录保存环境、充值模式、金额、渠道、价格快照、积分批次及核销证据。模拟数据与真实钱包采用可验证的隔离措施，防止模拟积分流入真实资金经营环境。具体使用独立环境还是独立账户账本，在实施设计阶段确认。

“我已付款”及截图仅记录用户声明，不直接视为到账。后续真实渠道已选定支付宝和微信付款码；真实核销依据、账号与具体付款码待提供，当前尚未启用真实充值。

本次补充已明确后续收款渠道为支付宝和微信付款码，当前仅使用模拟二维码图片，不填入真实收款信息。图片需明确标注模拟测试且不引导实际转账；网站更换为真实付款码后，仍通过用户付款声明及后台核销流程入账，不因展示二维码而自动确认到账。真实付款码、收款账号及到账核验证据待用户提供。

### 4.3 账本不变量建议

- 金额采用精确定点表示，积分精度及换算取整规则待决策；账本关联充值、消费、退款、失效或人工调整来源。
- 入账、扣减、过期、释放和退回均有唯一业务标识及可追溯明细；重复请求或并发处理不重复记账。
- 钱包可用量与批次可用量一致；预留量单独记录，扣费不得产生未授权负余额。
- 人工调整以新增调整记录进行，保留操作人、原因及审核记录，禁止静默改写原流水。
- 消费记录分摊到积分批次；有效期展示与后台过期任务使用一致的时间边界。

### 4.4 已确认的异常充值处理

订单已关闭后付款，人工核实到账后由管理员批准补记积分，并关联原订单。少付或多付时按实际到账金额折算普通永久积分，不享受原优惠包价格；此规则同样适用于关闭后金额不符的补记订单。核实到账仍是入账前提。充值上下限、非整数实际到账金额的折算精度、异常记录和对账证据等剩余事项见第13章。

## 5 订单状态与数字商品权益

### 5.1 建议状态模型

以下为实现建议；状态名、迁移权限和异常处理须随规格确认。系统不应仅靠前台按钮限制状态迁移。

| 对象 | 建议主流程 | 必须覆盖的分支 |
| --- | --- | --- |
| 充值订单 | 待付款 → 已声明付款 → 待核销或待大额审核 → 已入账 | 超时关闭、核销驳回、异常待处理 |
| 兑换订单 | 已创建 → 余额校验与扣减 → 已交付 | 余额不足、重复兑换、交付失败补偿 |
| 退款申请 | 待审核 → 已批准 → 已退积分 | 驳回、重复执行、权益处理 |
| API 订阅 | 待生效 → 生效中 → 已到期 | 额度耗尽、停用、续费与超额处理 |
| 激活授权 | 可激活 → 已激活 | 解绑、撤销、到期是否适用待定 |

2小时从订单创建起算；已声明付款的订单转待核查，不自动关闭。关闭与核销竞态、重复执行及状态纠错必须保持一次入账和可审计。关闭后到账由管理员批准补记，不允许重复点击直接入账。

### 5.2 已确认权益 F05

兑换付费软件后可永久下载已购买版本，同一大版本内免费更新，跨大版本可另行收费。每个商品可配置“仅下载”或“激活授权”。文档和网盘资源兑换后永久出现在“我的资源”中，可查看与重新下载。文件支持服务器、本地或对象存储与外部网盘链接。

### 5.3 权益实现建议

商品与权益分离：订单记录购买时的商品、版本范围、授权方式、积分价格及条款快照；权益引用对应版本和资源。发布新版本或下架商品不能直接删除已有购买记录及权益。

访问下载地址、提取码、文件与激活接口时校验权益。对象存储使用短时授权地址；外链可由平台在授权后展示，但外链的再次传播和第三方失效无法单靠平台鉴权解决。外链失效优先补交，无法恢复时进入退款审核。

永久权益包含历史版本持续可交付的运营责任。已确认保留已购版本，不能把“永久”静默改为只保留当前版本；具体备份方式及第三方撤权后的处置仍需明确。

### 5.4 已确认的软件授权与退款规则

每个商品可配置激活设备数，默认1台；用户申请换机，由客服审核后解绑并留记录。V1.0采用在线激活和验证。退积分后撤销平台下载与资源访问权益，同时撤销激活授权；已下载到用户本地的文件无法远程收回。重复兑换同一已拥有权益时提示并进入“我的资源”，不重复扣积分。

设备标识、激活码生成、大版本归属的管理方式及在线验证频率在实施设计中明确。

## 6 API 服务与计费

### 6.1 已确认需求 F06

每个 API 可配置按次调用或按周期订阅。每个套餐可配置调用额度、周期与超额计费规则。用户可创建多个 Key，分别设置权限及调用限制。免费 API 也要求注册取得免费 Key，并设置调用频率与额度。V1.0 交付完整 API 能力，包括多 Key 权限、限速、调用统计和在线调试。

### 6.2 建议请求处理链

请求标识 → 验证 Key 与所属用户 → API 权限检查 → Key 及账户限速 → 订阅和积分资格检查 → 原子预留额度或积分 → 调用 API → 依据计费事件结算或释放 → 写入用量和审计记录。

在线调试复用正式鉴权及计费入口，使用用户自己的Key，正常计费，调试前明确提示；不能绕过额度和权限。敏感数据展示及脱敏细则仍需明确。

### 6.3 可靠性与安全建议

- Key 可创建、停用、撤销和轮换，明文只在创建时展示；平台保存验证摘要及掩码标识，日志不得泄漏完整 Key。
- 额度及余额的最终事实保存在 MySQL；Redis 限速可加速判断，但不能单独充当积分账本。
- 计费请求记录唯一标识、API 与价格快照、预留及结算状态、耗时和结果；失败和超时均不扣积分或套餐额度；上游成功而平台超时也不得事后对用户补扣，保留不含敏感内容的异常记录用于内部对账。
- 重复结算不得重复扣费；重试代表同一计费事件还是新的调用，由计费规则决定，不能简单把所有重试合并。
- 多个Key共享账户或订阅总额度，每个Key可额外设置更低限额，不能通过多Key绕过总额度。
- 不默认保存请求正文、敏感返回数据或凭据；调用日志的字段、脱敏和保留时间待确认。

### 6.4 API 验收关注点

同时验证余额不足、额度耗尽、周期边界、限流、Key 撤销、权限变更、并发超扣、上游失败、超时重试、结算中断恢复和统计对账。用量与消费流水须能追溯至同一计费事件。

### 6.5 已确认的计费与周期规则

仅成功调用扣积分或套餐额度，失败和超时不扣。套餐额度用完默认停止调用，用户主动开启后才允许按超额规则扣积分继续使用。订阅手动续费，到期前提醒；套餐配置固定天数，从开通时起算，周期结束剩余额度清零、不结转。

提前续费从当前订阅到期时接续，已到期则从续费成功时起算。已购买订单保留原条款，新购买与续费采用新价格。后台账务与报表统一北京时间，前台明确显示时区。每API的成功判定、价格、流式场景和套餐变更等剩余细则见第13章。

## 7 客服 通知与反馈

### 7.1 已确认需求 F07 与 F08

允许游客咨询，可选留下邮箱；充值问题要求登录。多客服默认抢单，管理员可手动转派。无客服在线时允许留言，并可通过邮件通知客服。聊天支持文字、图片和截图；后台配置记录保留期限，用户能查看自己的历史会话。

同时提供公开留言板与私密意见反馈。用户收到客服回复或充值成功时，以站内通知为基础，可选择是否接收邮件。业务邮件默认关闭，由用户主动开启，站内通知始终提供。游客在原浏览器查看会话历史；其无账户时的通知访问凭据与会话凭据关联。

### 7.2 建议会话流程

发起咨询 → 进入待接单池 → 客服原子抢单 → 处理中 → 管理员按需转派 → 结束。离线留言进入同一可追踪队列。已接单客服离线后保留原负责人，由管理员按需转派，不自动回抢单池。两个客服同时抢同一会话时只能一人成功；转派及结束应记录操作人、时间和原因。

建议以服务端消息记录为准，推送只作送达通道。断线重连按消息序号补取，重复发送采用客户端消息标识去重；未读数按已读游标计算，避免刷新后遗漏。消息送达、已读语义和附件失败重试规则待确认。

### 7.3 数据与权限建议

用户仅可访问本人会话。游客使用原浏览器的不可猜测访问凭据查看历史。清理浏览器后，仅在能核实身份或原会话凭据时人工恢复，无法核实则新建咨询；登录后会话关联方式仍需明确。不能通过自报邮箱或订单号读取他人充值信息。

聊天图片支持JPG、PNG、WebP，单张默认最多10MB，后台可调整；校验实际类型，限制可执行内容，图片与截图使用相同安全处理。聊天记录默认保留180天，后台可调整。聊天记录删除、附件清理、通知摘要和备份保留应匹配保留策略。公开留言审核通过后发布，私密反馈始终不公开。

### 7.4 通知与桌面边界

站内通知建议持久保存，可标已读并关联业务对象。邮件支持按用户偏好发送、失败重试及投递记录。业务邮件默认关闭，可由用户主动开启；邮箱验证与密码找回邮件不受业务邮件偏好影响。邮件服务商、频率及客服接收名单待提供或确认。

V1.1 Windows 程序复用网站账号与通知服务，显示登录状态、未读数、托盘和系统提醒，并快速打开后台。桌面应用技术选型、支持的 Windows 版本、升级分发和后台运行方式不属于已确定规则。V1.0 需保留可复用接口设计，但不要求交付桌面程序。

## 9 技术架构与部署建议

### 9.1 已锁定约束 F11

后端 Java 17 与 Spring Boot，前端 Vue 3，数据库 MySQL。主站海外部署，结合 CDN 优化国内外访问。开发测试复用现有资源，生产使用独立海外服务器。初期月度基础运营预算暂不限制，优先稳定、安全和可运营。采用 GitHub、自动测试与自动部署流水线。

### 9.2 建议逻辑架构

浏览器与 API 客户端 → HTTPS 入口及 CDN → 网站前台或后台与业务 API → Spring Boot 模块化单体 → MySQL、文件存储和必要的缓存。客服通过持久消息服务加实时推送连接；定时任务负责订单关闭、批次过期、订阅周期及清理。

前台采用Vue 3体系的Nuxt渲染公开内容，Nuxt已在Q42选定；后台采用Vue 3，Spring Boot采用模块化单体，Redis用于辅助缓存和限流。WebSocket、WAF、对象存储品牌、邮件提供方及容器化细节仍为技术建议，待实施方案明确。

### 9.3 模块职责与接口边界

| 模块 | 主要职责 | 对外边界 |
| --- | --- | --- |
| 账户与权限 | 身份、重置、后台授权 | 注册登录、个人资料、角色操作 |
| 商品与内容 | 目录、版本、双语、SEO | 浏览搜索、运营发布 |
| 交易与钱包 | 订单、核销、批次、退款 | 充值、兑换、审核、流水 |
| 权益与交付 | 我的资源、下载、激活 | 权益检查、授权访问 |

| 统计与系统 | 事件、报表、配置、审计 | 后台报表与系统管理 |

### 9.4 部署与恢复原则

建议开发测试和生产隔离数据库、密钥、存储及邮件；CDN 只缓存允许公开的数据，个人页面、Key、钱包和授权下载禁止公共缓存。对国内外实际网络分别测试，不能以海外加 CDN 替代实测。

流水线建议包含构建、自动测试、依赖及密钥检查、测试环境部署、数据库迁移验证、生产发布与回滚。已确认生产发布前由管理员批准，批准后由自动部署流水线执行。数据库备份、文件备份、恢复演练、监控告警与凭据轮换一并设计；已确认生产配置确定后提交并发、响应时间及备份恢复目标，经用户确认后据此验收；具体数值尚待定。
