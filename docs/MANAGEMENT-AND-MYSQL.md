## 2 来源 IP 与后台配置

在“系统管理 → 配置管理”维护以下参数，不需要改配置文件：

| 配置键                           | 默认值          | 含义                                                                                   |
| -------------------------------- | --------------- | -------------------------------------------------------------------------------------- |
| `security.trusted_proxies`       | `127.0.0.1,::1` | 后端信任的直接网关 IP，逗号分隔，使用精确 IP。                                         |
| `security.trusted_front_proxies` | 空              | 网站网关前方可信反向代理/CDN 的实际连接 IP；未配置时以浏览器到网站网关的连接 IP 为准。 |

网关覆盖 `X-AIWYW-Peer-IP`，并把实际连接方追加到转发链。后端仅在直接连接方可信时使用该信息；进一步解析转发链还要求前方连接 IP 已显式受信任。从链右侧查找首个不可信节点，不直接接受客户端填写的第一个转发 IP，不对主机名发起 DNS 查询。

API 使用显式服务端网关转发，确保来源处理先于代理执行；固定内部目标，保留 HTTP 状态、多 Cookie 和流式上传/下载，服务端不跟随重定向。生产有反向代理时应在后台录入实际拓扑，避免把所有来源都记成代理或扩大信任范围。

## 3 本地资料与迁移结果

- 地址：<http://127.0.0.1:3000/>；后台：通过受保护的 backend/data/staff-entry 读取该部署的入口值，打开 http://127.0.0.1:3000/入口值/login。
- 当前运行库：`aiwyw_local_review_20261105164506`，MySQL 8.4.11，连接要求 TLS。用户提供的本地凭据文件只用于此次连接，未写入源码、日志或交付文档。
- 源 H2 的 **64 张表**逐表复制，核对行数及规范化数据 SHA-256 后才切换加密引导连接。原 H2 文件和根密钥保留，原管理员密码、MFA、商品资料和静态文件未重置。
- 迁移前备份：`.local/backups/mysql-migration-20261105164506/`；迁移后备份见 `.local/active-release.json` 的 `validationBackup`，包含 MySQL SQL 导出及成套数据文件。SQL 导出已实际成功，临时客户端凭据文件随即删除。
- `backend/data/mysql-migration-report.json` 保存逐表行数和摘要；`validation-data-report.json` 保存本批次及生成后总数；`validation-accounts.txt` 保存本地测试账号及临时密码。以上文件仅当前 Windows 账户可读，全部被 Git 忽略，不能作为公开静态资源。

迁移工具在测试源码 `LocalMysqlMigration` 中，不提供网站入口。它要求站点已受管停机、备份中的主密钥及原引导连接与源一致，只能从 H2 迁移到全新 MySQL 库；已有同名数据库直接拒绝，不覆盖、不清空已有库。失败时保留源文件及备份，不以创建空安装修复错误。

数据生成工具 `LocalValidationSeeder` 同样没有网站入口，必须显式传入本地确认参数，且实际连接数据库名须以 `aiwyw_local_review_` 开头。它使用独立样本管理员完成真实密码登录及 TOTP 绑定后执行审核，不关闭 MFA 策略。生成期间停用调度器，完成时清除本批新增邮件队列，保留原队列，避免向已有真实地址发送合成内容。

## 5 结构及人工排查

新增 `object_origin` 保存业务类型、原主键、创建时间、创建账户，联合主键防止重复来源。`config_audit`、`catalog_audit`、`storage_audit`、`finance_audit` 增加可空 `source_ip`。结构注释见 [MANAGEMENT-SCHEMA.sql](database/MANAGEMENT-SCHEMA.sql)。实际 MySQL 64 张表的表注释和全部字段注释均已核对，无遗漏。

`V009_MERGED_APPLICATIONS` 仅一次合并旧菜单授权；`V010_OBJECT_ORIGIN` 仅回填有证据的创建来源。不要手工删除迁移记录来反复执行升级。不要批量把空创建人或空 IP 改为当前管理员；这会破坏审计真实性。不要单独替换根密钥或引导连接，不要通过手工改余额、删除退款分摊或授权表来修复交易。

源码和测试数据分离。恢复时数据库 SQL、`master.key`、`bootstrap.enc`、存储及静态文件必须来自同一备份批次。迁移前 H2 备份仍可用于受控回退，但生成后新增数据不会自动反向同步到 H2。
