# 详情导航、客服回复、充值备注和 API 代理

2026-11-05追加的六项优化。业务配置继续通过后台维护，原有 MySQL 数据、静态快照、账户及积分交易规则保留。

## 详情与页脚

- 首页应用名称及“查看详情”、应用列表“查看详情”、API目录名称及“查看详情”、文章/教程/FAQ/案例的内容卡片均在新浏览器页签打开，带 `noopener noreferrer`。下载按钮继续执行原下载/兑换交互。
- 应用静态详情保留首页品牌、可维护导航、语言切换和页脚，面包屑为“首页 / 所有应用（或API服务）/ 应用名称”。内容详情显示对应文章、教程、FAQ或案例路径。API服务详情为 `/api-services/{slug}`，显示“首页 / API服务 / 名称”，并提供平台地址、公开说明、价格及套餐。
- 旧的已发布应用和内容不需要重新发布：服务端先校验原快照摘要，再用缓存公开导航装配头尾。原文件及交付快照不改写。ETag包括公共外壳，栏目和备案信息变化可正确失效；应用原脚本CSP摘要保留，文章仍可在禁用JavaScript时完整阅读。
- 页脚居中保留客服入口、备案号和域名，去掉账户、文章入口及原站名标语。未填写备案号时显示 **模拟ICP备00000000号（占位）**。真实号码仍从“系统管理 → 配置管理 → 网站信息 → 备案号”替换；已有真实配置不会被覆盖。

## 栏目与客服

“系统管理 → 首页栏目”统一维护应用展示区、文章导航和 API 导航。API可编辑双语名称、启用/停用、删除后重建；显示时始终位于顶部导航末尾。API和文章导航不占最多六个应用展示区域的限额。停用导航仅隐藏入口，不停用已配置服务、不撤销已购订阅；服务启停仍在API管理维护。

`V011_API_NAV` 只迁移一次原固定API入口，之后管理员停用或删除不会被重启自动恢复。栏目名称、规则及权限不因升级重置。

在线会话“查看”或“抢单领取”打开独立工作页签；相同会话切换到已有页签，不同会话分别保留草稿。回复、图片、转派等在回复页签操作，列表不再内嵌聊天框。关闭有未发送内容的页签仍提示处理，不自动发送草稿。心跳和轮询只在对应页签可见、浏览器前台时进行；原抢单、参与方权限、私有图片授权保持服务端验证。

## 四位付款备注码

每笔新充值订单在创建事务内随机生成 `0000`—`9999` 的四位字符串，连同订单保存。允许重复，不增加唯一约束；前导零必须保留。同一幂等请求的重试返回原订单及原码，提交付款声明或审核不会重新生成。

用户创建订单后的二维码弹窗醒目展示备注码并提示填写到支付备注；历史列表也展示。核销列表和审核弹窗同时展示账户及备注码，可按昵称、邮箱或备注码检索，再结合实际金额、到账记录和订单状态匹配。备注码不是付款凭证，也不触发自动核销。旧订单未曾发放备注码，保持空值并标明未生成，不能回填成曾经告知用户的号码。

当前仍为模拟收款。上传真实付款码或存在备注码均不自动开启真实充值。

## API平台入口与真实服务

新增API默认选择“代理真实HTTPS JSON服务”，真实地址不再被内置计算模式隐藏。

| 字段 | 作用 |
| --- | --- |
| 接口标识 | 创建后固定，组成平台调用路径，不是供应商地址。 |
| 平台调用地址 | 页面自动显示 `https://网站域名/api/v1/invoke/{标识}`；用户使用平台Key向此地址POST JSON。 |
| 服务类型 | HTTPS JSON代理，或已有文本统计/SHA256内置服务；内置服务不需要虚构上游地址。 |
| 真实服务地址 | 代理模式必填，管理员配置的固定HTTPS地址；不接受调用者提交目标URL。 |
| 真实服务请求方式 | POST把用户JSON作为请求体；GET把JSON对象中的标量字段编码到查询串，保留地址中的固定查询参数。嵌套对象/数组明确拒绝，不能猜测供应商编码。 |
| 自定义请求头 | 字符串JSON对象，如 `{"X-API-Key":"供应商密钥"}`；最多20项，加密保存且不回显，留空保留，明确勾选才清除。 |
| 上游Bearer凭据 | 加密保存，不使用用户的平台Key冒充供应商凭据；留空保留，明确清除才删除。 |
| 成功字段Pointer与JSON值 | 例如 `/success` 与 `true`，或 `/code` 与 `0`；2xx且标量精确匹配才成功结算。 |
| 公开说明/英文说明、成功扣分、启停 | 说明用户应提交的JSON字段及用途；计费、套餐、Key权限与既有规则一致。 |

超时、请求/响应上限、并发、频率默认值等继续在配置管理的API相关配置维护。该通用适配器支持非流式JSON GET/POST；没有自动实现供应商专属签名、OAuth换令牌、二进制上传或流式协议。若服务需要这些能力，不能仅填写URL就视为已经完成专属适配。

平台完成身份、Key、权限、限速、配额/积分预留后再请求真实服务，成功才结算；失败和超时按原规则释放。不会转发用户Cookie、平台Key或任意客户端头。固定传输头由平台生成，自定义头禁止Host、长度/分块、连接控制、Cookie和Authorization等敏感控制头；Bearer由专门字段设置。

上游继续限制公共网络HTTPS/443，检查全部DNS结果并固定连接IP，校验证书及主机名，不跟随重定向。上游地址、凭据和请求头不进入公开详情、公开API目录、操作日志或后台明文回显。具体供应商地址、请求字段、凭据及成功规则需要站长录入后联调；本轮测试没有替站长假造真实供应商联调结果。
