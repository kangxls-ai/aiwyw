# 本机打包与阶段部署

用户已授权：后续每个开发阶段完成并检查通过后，自动部署到本机供查看，不重复询问本地编译、备份、重启权限。此授权不改变正式服务器发布和真实收款的既有批准条件。

## 本机工具

已安装 Apache Maven 3.9.11，安装包通过 Apache 官方SHA-512校验。目录为 `%LOCALAPPDATA%\Programs\Apache\Maven\apache-maven-3.9.11`；用户级MAVEN_HOME、PATH及JAVA_HOME已配置。JDK21运行Maven，项目仍按Java17目标编译。新开终端可运行 `mvn --version`。

## 查看和操作

- 首页：<http://127.0.0.1:3000/>
- 首次安装：<http://127.0.0.1:3000/install>
- 管理后台：<http://127.0.0.1:3000/admin>

首次安装码保存在 `backend/data/install.token`，仅安装前存在；从该本地文件复制到安装向导，然后设置自己的管理员邮箱和密码，并绑定验证器。不要将安装码或密钥上传到仓库。未提供的商品资料仍为草稿，首页不会填充虚构商品。

项目根目录提供以下入口：

| 文件/命令 | 功能 |
| --- | --- |
| `start.cmd` | 首次执行会编译部署；已有部署则直接启动/打开 |
| `open-local.cmd` / `npm run open:local` | 打开已部署版本；服务停止时后台启动 |
| `update-local.cmd` / `npm run deploy:local` | 编译、测试、备份并更新本地版本 |
| `stop-local.cmd` / `npm run stop:local` | 优雅停止本项目，保留数据和版本 |

已创建桌面“AIWYW”快捷方式，可直接打开；服务停止时会先启动。服务隐藏在后台运行，关闭查看网页不会停止。日志和运行状态在项目 `.local/`，仅当前Windows账户可读写。网页仍然不展示测试版本横幅；模拟收款保留其业务标识。

## 每阶段更新流程

`scripts/deploy-local.ps1` 默认依次执行：

1. 验证Maven/JDK/Node，检查3000、18080是否属于本仓库；遇到其他应用占用直接停止操作，不终止其他服务。
2. 保留上一版运行副本，停止本项目进程；新受管后端通过私有stdin管道关闭Spring上下文与数据库连接，不开放网络停机接口。
3. 备份 `backend/data/`。若安装选择MySQL，同时用mysqldump导出该应用库；密码不放命令行，临时凭据只在受保护目录并在使用后删除。备份失败则不部署新版本。
4. `mvn -B -ntp -f backend/pom.xml clean verify`，执行后端测试与打包。
5. 前端类型检查、生产构建、隔离数据的浏览器端到端检查。浏览器流程不写真实站点数据。
6. 将产物复制到独立 `.local/releases/时间标识/`，由后台进程管理器启动。运行文件与工作区编译目录隔离。
7. 验证站点、目录和安装状态接口，成功后记录阶段及检查结果；更新失败则尝试恢复上一版运行文件，不自动覆盖现有数据库。

当前本地H2停机备份与发布流程已验证。MySQL备份分支在实际使用对应数据库时要求已安装mysqldump及足够导出权限；它不代替正式生产数据库、远程对象存储的完整备份恢复验收。

## 本地资料与故障排查

- `.local/active-release.json`：最近成功的本地发布位置。
- `.local/last-deploy.json`：最近一次部署结果、备份位置、检查列表。
- `.local/runtime-state.json`：本次后台进程及应用日志目录。
- `.local/logs/`：受保护的运行日志；可能包含首次安装凭据，不公开分享。
- `.local/backups/`：停机数据备份及必要时的数据库导出，禁止提交仓库。
- `.local/releases/`：独立版本产物，可用于恢复上一版。

不要移动正在运行的版本目录，也不要删除 `backend/data/master.key`。数据库恢复和极端情况下的人工干预见 `MAINTENANCE.md`。`.local/`、运行数据及密钥已从Git排除。脚本仅为当前进程使用执行策略参数，没有修改系统全局PowerShell执行策略。

旧的 `npm start` 仍保留为开发人员直接运行编译目录的入口；日常查看用上述受管入口，避免同时启动两套服务。
