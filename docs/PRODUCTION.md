# 微云湾生产部署与本轮验收

适用域名：`www.aiwyw.com`。本轮交付生产启动模式、上线检查、Linux单机部署模板和干净发布包；不包含远程服务器部署或真实支付开放。

## 上线边界

- 首次生产安装使用**新的空MySQL数据库**。本地验收库含合成用户、鼓励值、API、捐赠记录，生产模式检测到 `LOCAL_REVIEW_` 迁移标记会拒绝启动，不应通过删除标记绕过。
- 生产模式已安装数据库只允许MySQL。安装前H2仅承载安装引导；安装向导禁止选择H2。没有默认生产管理员或通用密码。
- 用户注册验证、密码找回和客服通知通过SMTP队列投递。POP3/IMAP仅提供只读连接与认证诊断，不能替代SMTP发信。
- **真实收款尚未开放**。上传支付宝/微信收款码不启用真实收款，当前捐赠、鼓励值交易仍为模拟流程。可先部署工具/内容站；不能据此宣称真实商业收费已经验收。
- 保留明确的模拟收款提示；不在正常应用页面增加“测试版”标识。网站备案号留空时显示占位，收到号码后在后台填写。

## 发布包与运行条件

建议单机起步：Linux、Java 17或兼容运行时、Node.js 24、MySQL 8、Nginx，至少4GB内存并按实际文件容量准备持久磁盘。模板为单机进程设计，不应未经改造启动多个共用本地存储的实例。

源代码构建（先运行仓库CI同样的验证）：

```sh
npm ci
mvn -B -ntp -f backend/pom.xml clean verify
npm run typecheck
npm run build
npm run test:e2e
node scripts/package-production.mjs
```

最后一条输出 `.local/production/` 下的目录和 `.tar.gz`。包中只有后端JAR、前端独立运行文件、部署模板、手册和SHA256清单；不含 `backend/data`、本地账号、MySQL密码或主密钥。`release.json`记录源提交、是否存在未提交修改及构建平台。正式服务器优先使用Linux CI生成的包；其他平台构建的包须在目标Linux复验。

GitHub CI在主分支全部检查通过后生成 `production-linux` 下载附件，不自动发布到服务器。

## 首次安装

1. 安装上述运行环境，创建独立非root系统用户 `aiwyw`。解压发布包至 `/opt/aiwyw/releases/<版本>/`，校验 `sha256sum -c SHA256SUMS`，将 `/opt/aiwyw/current` 指向该版本。
2. 创建 `/var/lib/aiwyw`，仅允许 `aiwyw` 用户读写。不要复制本地验收数据目录。为MySQL创建独立空库和专用账号，权限限于该库；升级需要建表/加列权限，禁止公开3306端口。远程MySQL当前连接强制TLS；如要求服务端身份校验/专用CA，应先完成相应连接策略适配，不能把仅加密视为身份已验证。
3. 将包内 `deploy/aiwyw.service` 安装到 systemd 服务目录。模板假设Node位于 `/usr/bin/node`、Java在服务PATH；如运行时路径不同只调整服务运行路径。`systemctl daemon-reload` 后启动服务。进程由systemd管理，任何一端退出会停止另一端并整体重启；正常停机最多等待35秒。
4. 后端只监听 `127.0.0.1:18080`，前端只监听 `127.0.0.1:3000`。安装真实HTTPS证书，按 `deploy/nginx.conf` 建立入口，先执行 `nginx -t`。公网仅开放80/443及受限运维入口，禁止暴露内部端口。安装期间可用管理员IP白名单保护 `/install` 与 `/api/install/`。
5. 从服务器受保护的 `/var/lib/aiwyw/install.token` 或服务启动日志取得一次性安装码。通过HTTPS打开 `/install`，测试MySQL连接，填写独立管理员邮箱和长密码，完成安装。安装成功后该入口拒绝再次初始化，不会覆盖已有用户库。
6. 使用安装完成页一次性显示的专属后台链接登录，并绑定管理员双因素认证。在“系统管理 → 配置管理”维护站点域名、邮件链接地址 `https://www.aiwyw.com`、邮件、存储、备案信息及安全策略。所有运营参数从后台设置，不编辑业务配置文件。
7. 单机Nginx模板的“前台可信反向代理IP”填写 `127.0.0.1,::1`，使来源IP正确还原；后端可信代理默认同样为回环地址。模板覆盖浏览器伪造的转发头。如果加CDN，须先单独配置其真实来源校验和可信代理链，不直接信任任意 `X-Forwarded-For`。
   模板同时固定转发HTTPS协议标记；登录、游客客服和访客Cookie统一在HTTPS入口设置Secure。内部端口必须保持仅回环监听，不能绕开入口对外开放。
8. 点击“生产上线检查”，逐项处理阻断项和待核验项。在生产服务器实际完成注册、邮箱验证、密码找回、文件上传下载、API代理超时/失败和客服通知验证，再开放访问。连接检查通过不保证邮件送达，必须实际查收并完成验证流程。

## 后台入口与账号锁定

- 每套部署首次启动会在受保护的数据目录生成独立的 32 位无横线 UUID，保存在 staff-entry 文件。登录地址为 https://你的域名/该值/login。前台、普通用户登录和公开内容沿用原地址。
- 已安装系统升级后，由服务器运维人员在受保护的控制台读取该文件。Linux 模板默认路径为 /var/lib/aiwyw/staff-entry。本地路径为 backend/data/staff-entry。启动时不打印入口值，公开配置和仓库不包含此值。反向代理、CDN 与监控日志也应保持对后台路径的保护。
- 后台登录、工作台及管理 API 共用专属前缀。管理会话 Cookie 只在该前缀下发送，和普通用户的会话隔离。升级后后台管理员应通过新入口重新登录。
- 默认 15 分钟内密码或动态码累计错误 5 次，暂停该账号新登录 15 分钟。设置可在配置管理的「账号与安全」调整。累计次数与锁定期限存于数据库，换 IP 或重启不会清除锁定。等待锁定到期，随后用正确密码和验证器登录。
- 若专属地址泄露，在停止本项目服务后把 staff-entry 以受保护文件方式移出数据目录，重新启动会生成新值。旧路径失效。管理员使用新路径重新登录；入口仍须配合角色授权和双因素认证。

## 网站品牌、备案与注册

- 在「系统管理 → 配置管理 → 网站信息」填写工信部 ICP 备案号和公安网安备案号。公安备案编号图标可在同一处上传。公安网安备案号包含 14 位数字时，页脚链接直达该编号的官方查询页。
- 「开放用户注册」默认关闭。开启并保存后，登录页显示注册入口。关闭时服务端也会拒绝新注册，已注册用户仍可登录、验证邮箱和找回密码。
- 保存公开配置会静态发布首页与用户登录页。可用「发布首页与登录页」手动重建。中英文分别生成，带查询参数的邮箱验证、密码重置等页面按请求渲染。首页快照每分钟允许刷新一次，让热门排行和统计更新。

## QQ邮箱测试

在“配置管理 → 邮件服务”点击QQ方案，可填入连接参数；不会自动替换已有授权码或开启发信开关。账号填写完整邮箱地址，发信地址与账号一致，密码使用QQ邮箱生成的授权码，不能使用QQ登录密码。先保存，再测试。

| 协议 | 主机        | 端口与加密                                 | 本系统用途                    |
| ---- | ----------- | ------------------------------------------ | ----------------------------- |
| SMTP | smtp.qq.com | 465 SSL/TLS（配置值TLS）；备用587 STARTTLS | 发送网站验证、找回密码等邮件  |
| POP3 | pop.qq.com  | 995 SSL/TLS                                | 仅连接和认证，不读取/删除邮件 |
| IMAP | imap.qq.com | 993 SSL/TLS                                | 仅连接和认证，不打开文件夹    |

QQ服务开启与授权码参考 [QQ邮箱帮助](https://help.mail.qq.com/detail/106/985)、[华为官方操作说明](https://consumer.huawei.com/cn/support/content/zh-cn16108643/)；服务器参数参考 [腾讯云企业集成服务官方文档](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)。协议服务必须分别在邮箱网页允许；部分账号受服务商策略限制时，以实际诊断结果为准。

诊断显示 `AUTH`、`TLS`、`DNS`、`TIMEOUT`、`CONNECT` 或 `DELIVERY` 和处理建议，不返回原始异常、密码或验证令牌。TLS证书检查始终开启。SMTP连接测试不会发信；“发送测试邮件到我的邮箱”只投递给当前管理员，成功表示SMTP已接收，不代表最终入箱。

自动投递失败保留加密正文并逐步退避重试，最长每小时一次。配置页显示等待数量与失败分类；成功后清除错误分类和队列正文。不要反复点击注册制造大量重试邮件。若授权码变更或服务商风控，先完成连接诊断，再实际查收测试邮件，最后启用自动邮件服务。

原“邮件设置”为空占位，与配置中心重复，已移除；旧入口跳转到邮件服务。旧的独立 `email` 菜单授权删除，不将它自动升级成能修改全部配置的 `settings` 权限。已有管理员配置权限保持不变。

## 栏目维护与性能边界

- 首页默认显示排序第一的启用栏目；API仍遵守此前确认的导航末尾规则。显式 `/?section=<ID>` 可切换，停用或失效ID回退到第一个启用栏目。无内容时展示空状态，加载失败可重试。
- 首页仅加载栏目元数据和当前栏目的限量短卡片，不携带所有商品富文本。更多页服务端分页，保留名称搜索和应用标签筛选。
- 人工选品通过搜索弹窗数据库分页，默认20项、可选10/20/50项；跨页选择保存在草稿集合，取消不改动编辑表单，确认后可拖动、上移、下移或移除，保存栏目后才公开生效。
- 每个人工栏目最多300项，应用、直接API、文章/FAQ/案例可混排。内部兼容旧字段 `productIds`：应用保留UUID，API为 `api:<UUID>`，内容为 `content:<UUID>`。服务端参数化查询校验引用，不根据传入类型拼接表名。删除内容显示占位并要求移除；未上架、未发布、已停用条目不公开。
- 新页面显示发布快照，不提前泄露草稿正文、私有下载地址或API上游密钥。自动应用栏目沿用已有目录缓存；全站 `/apps` 的全量目录缓存属于现有设计，超大规模目录仍需独立扩展，不能把人工弹窗改造理解为全站无限容量保证。

## 更新、备份与回退

1. 先在独立测试环境验证新包；确认SHA256和提交号。停止 `aiwyw` 服务后，成套备份MySQL、完整 `/var/lib/aiwyw`（含 `master.key`、`bootstrap.enc`、静态发布文件及本地资源），并备份外部对象存储；备份加密且限制读取权限。
2. 密码不要出现在命令行或日志；可用权限0600的临时MySQL选项文件，完成后删除。不同时间点的数据库和密钥不可随意混合。丢失主密钥不能靠生成新密钥恢复旧密文。
3. 解压新包到新的版本目录，保持持久目录原位置，停止服务、切换 `current`、启动并检查健康、管理员登录和关键流程。本轮数据库只增加队列错误分类列并移除失效菜单授权，不删除交易记录。
4. 应用回退切回上一目录，不自动覆盖数据库。只有确认数据库损坏并评估数据差异后才按配套备份恢复，不能用旧库覆盖升级后新订单。
5. 定期在隔离环境实际恢复并核对订单、余额、静态页面、文件和密钥；仅“生成备份成功”不等于可恢复。生产峰值与持续压测须基于目标硬件、真实文件和上游限额执行。

本地自动部署继续保留原MySQL资料和主密钥，使用受管脚本备份、验证、切换版本；不会把本地直接切成生产库。
