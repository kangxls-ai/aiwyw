# API、客服与运营统计操作和维护

本阶段接通实际业务，不向正式安装写示例API、用户、聊天或交易。内置文本统计和SHA256适配器执行真实计算；站长从后台创建API后才能对外使用。当前积分仍在SIMULATED账本，真实收款没有启用。Windows客服托盘程序仍属V1.1。

## API管理与用户使用

后台“API服务 → API管理”维护固定调用地址、中英文名称和说明、适配器、成功按次单价与启停。“套餐与订阅”维护价格、额度、固定天数和启停，并分页查购买周期；“Key管理”查看脱敏前缀并停用；“调用统计”查询实际调用、状态、计费方式和时间。列表支持服务端分页、时间筛选及白名单排序，默认创建时间降序。

支持以下适配器：

| 适配器 | 输入与结果 | 成功标准 |
| --- | --- | --- |
| TEXT_STATS | `{"text":"Hello world"}`，返回Unicode码点数、按空白切分的词数和行数 | 本地完整计算成功 |
| SHA256 | text字符串，返回UTF-8文本的SHA256十六进制摘要 | 本地摘要计算成功 |
| HTTPS_JSON | JSON POST至后台配置的HTTPS上游，可配置Bearer凭据 | 2xx、完整有限JSON、指定JSON Pointer的值与配置的标量JSON值精确一致 |

HTTPS_JSON只访问公共网络443端口，检查所有DNS结果并固定实际连接IP，保留TLS证书及主机名校验；不跟随重定向，不接受调用者提供URL，不支持尚无成功边界的流式输出。响应不满足业务成功字段时，HTTP200也不计费。上游凭据加密、不回显，留空保留、明确清除才删除。具体第三方接口资料、凭据、成功条件和生产网络需要站长配置及实际联调，不能用内置计算或测试替身冒充第三方验收。

前台 `/api-services` 提供双语目录、搜索、套餐、Key、订阅、调试及调用历史。“我的账户”提供入口。免费API同样要求已验证邮箱和Key。可创建多个Key，设置API权限、每分钟上限、每日成功调用上限和有效期；每日0表示不另设更低上限，不取消账户与套餐限制。Key默认最多20条，可从配置管理调整；已使用Key保留审计，可停用或轮换，不物理删除。轮换保持配置、立即使旧凭据失效，新原文与创建一样只展示一次；历史调用保存原前缀。已进入处理的请求按预留时条款完成结算。

若需要API进入首页栏目及应用搜索，在“应用管理”发布同slug的API类型商品作为介绍入口；点击进入API中心，实际套餐和按次价格以API服务配置为准，不走软件兑换或下载。应用介绍的展示状态、套餐是否可新购、API是否接受调用分别维护；停售套餐保留已购周期，停用API则阻止新调用。不会把营销页面的展示价格直接用于API扣费。

程序调用示例，替换占位符后使用：

```http
POST /api/v1/invoke/your-api-slug
Authorization: Bearer <YOUR_KEY>
Idempotency-Key: <UNIQUE_REQUEST_ID>
Content-Type: application/json

{"text":"Hello world"}
```

幂等标识为8—80位英文、数字、短横线或下划线。同一账户、API、标识的相同输入只执行并结算一次，不同输入拒绝；多Key重试也不能重复扣费。进行中返回409，应保留原标识查询/重试，不能盲目换标识重放有副作用的上游请求。终态失败不重新执行；确需一次新调用才使用新标识。成功响应短期加密保存，默认7天；到期删除正文，最小幂等/计费事实保留，旧标识返回410而不重新扣费。请求正文不入调用日志，只保存摘要。在线调试选择本人Key，走相同权限、限速及正常计费路径。

## 计费、周期与异常

1. 调用开始时锁账户，检查邮箱、Key、权限、频控及当前周期，预留一次额度或按最早到期顺序预留积分批次。外部调用期间不持有数据库事务，其他Key不能消耗同一份预留。
2. 成功才结算预留；失败、超时释放。失败释放保留原积分到期时间，不延长原期限。流水中的“API积分预留”是可用余额占用，不是收入。成功记录与结算同事务提交。
3. 上游进程中断或无法确认结果时，恢复任务记UNKNOWN并释放，绝不自动重放上游。工作池、请求/响应大小和包含DNS/写入的整体截止时间有界，超时主动关闭套接字。
4. 各Key共享账户/订阅总额，同时受自身更低的分钟与每日限制。分钟限速计尝试；日额度计成功和进行中预留，按开始时北京时间日期归属。无有效套餐的付费按次调用需用户主动启用；有效周期额度耗尽默认停止，超额扣分也需单独主动启用。
5. 每次套餐购买保存价格、额度、天数和起止时间。提前续费接最后已购有效周期末尾，全部已过期则从购买时起；旧订单不跟随当前套餐改价。周期余量不结转，未来周期不能提前消费。到期提醒通过站内通知及用户自选业务邮件投递，不自动续费。
6. 套餐没有成功调用且没有在途调用，才可申请整单退积分。申请后该周期暂停调用；客服/管理员逐单审核，不能自审。批准后撤销周期，恢复原批次；已过期部分按已确认规则延30天，重复批准不重复退款。驳回后恢复周期。退款不重写其他已购周期的时间。
7. 已使用套餐不提供标准部分退款。异常通过“交易管理 → 积分流水 → 人工积分调整”由管理员处理，要求目标账户、正负积分、赠分期限、原因及幂等标识，禁止本人调整。赠分成本0；负调整按原批次顺序，余额不足整单回滚。记录调整、分摊、流水、通知和财务审计，不能以此伪造人民币退款或充值收入。

## 客服、游客和反馈

前台 `/support` 支持游客咨询和可选邮箱；充值咨询必须登录。游客凭HttpOnly Cookie读取原浏览器历史，不凭会话编号开放内容；原浏览器登录后，未归属账户的会话和反馈关联当前账户，随后仅该账户可读。共享浏览器切换到其他账户不取得前一账户的历史。

清理Cookie后，输入会话编号和原留邮箱申请一次性核验链接，匹配与否对外使用同样提示。成功消费后换发凭据、旧游客凭据失效；默认30分钟，不能重用。修改联系邮箱作废旧核验链接。无法核验则新建咨询，不能直接按邮箱文本返回历史。找回邮件属于必要验证邮件，不受业务邮件偏好控制。

后台“客服与反馈 → 在线会话”显示未领取及本人会话，管理员可查看全部并转派。抢单、转派及状态版本在同一会话锁内检查，两人抢同一单只成功一次。只有当前负责人可回复，管理员需先转派给自己才回复；离线保留负责人。心跳只在在线会话页签可见且浏览器前台时发送，默认90秒未更新视为离线。

文字和JPG/PNG/WebP图片可发送，支持粘贴截图。图片通过存储管理当前本地/S3配置上传，采用私有CHAT用途，不进入公开媒体或普通资源库。查看图片仍校验会话归属，消息引用保护文件。发送使用客户端幂等键和递增序号；增量轮询默认3秒，支持加载更早消息，已读游标只能前进，不因重试重复累计未读。工作台顶部显示本人未读与待领取数量。

没有客服在线时照常保留消息，并按配置的客服邮箱投递离线提醒，同会话默认至少间隔10分钟。站内通知始终给登录用户；业务邮件默认关闭，登录用户在账户偏好开启，游客自愿选择回复邮件。邮件不包含私有正文或图片。

“公开留言”先审后展示，仅公开已批准内容和回复；“私密反馈”始终不进入公开接口。用户可查本人提交状态及回复。前后台内容按纯文本渲染，不能借留言执行HTML。后台按各自菜单授权分开处理。

聊天默认保留180天，以最后活动时间为准，后台可调；清理消息、附件引用和资源。未发送图片满一天清理，删除对象存储失败的私有孤立文件在后续任务重试。备份仍按备份保留策略管理，清理当前库不表示历史备份已删除；恢复旧备份后应重新执行到期清理。

## 统计口径

“工作空间 → 运营统计”提供访问、首次来源、关键词、注册队列D1/D7/D30留存、商品/API收入、充值、API成功失败与耗时、客服及反馈统计和收入CSV。统计菜单服务端独立授权，默认内置管理员/财务持有；迁移只授予一次，之后撤销不会被重启覆盖。

- 日界及报表日期为北京时间，范围最多366天，默认近30天。来源只保存首次来源域，不存完整URL或IP。匿名标识保存摘要；行为按同访客、页面/词、自然日去重，默认排除当前有后台菜单的账号，可关闭行为采集。浏览器拦截、Cookie清理或未上报可能少计；行为不作为账务凭据。
- 注册留存以注册日为队列，统计第1/7/30个北京时间自然日登录访问的账户；不猜测游客与账号关联。最近31个注册日展示，未到观察日不填0。更早行为是否可查询受配置保留期约束，默认400天。
- 充值金额来自已核销的实际金额；消费成本来自购买/调用时积分批次的真实充值成本分摊，赠分成本0；标准退款在批准日冲回原分摊，跨期净额可为负。套餐收入按购买计一次，额度调用不重复算套餐收入。
- 真实与模拟账本独立，默认真实报告排除模拟，当前未开放真实收款时显示0。选择模拟仅作独立分析。此口径不是税务财务确认收入。CSV与屏幕同范围/账本，最小单位精确计算并防止文本被表格软件当公式执行。
- API耗时含上游，不等于平台自身耗时。客服首次响应只对已有答复的新会话计算，未答复不伪造0秒。

## 配置、恢复和部署边界

全部参数在“系统管理 → 配置管理”维护，涵盖API数量/超时/限速/响应保留、客服图片/轮询/保留/核验/在线/邮箱、统计开关与保留，以及Redis辅助配置。Redis默认关闭，启用后缓存公开API描述并辅助固定窗口限流；数据库始终执行权威配额检查。失败熔断后回退数据库，不放宽限制；提供后台连接检查。正式Redis、SMTP和具体云存储的连接应从后台配置和验证，不要求修改配置文件。

新增表及索引见 [OPERATIONS-SCHEMA.sql](database/OPERATIONS-SCHEMA.sql)，完整结构在IMPLEMENTED-SCHEMA.sql。维护时按用户账户锁检查调用RUNNING、wallet_hold及分摊、订阅held_count和流水；禁止手工改余额或把UNKNOWN直接改SUCCESS。先保留证据/备份，再重跑恢复任务或使用有审计的调整。修改存储连接不改变历史文件连接快照；密钥、库、资源文件须成套备份。

此阶段交付业务实现及本地运行，不代替生产容量、安全性能、外部服务和恢复演练验收。生产配置和阈值仍按既定Q45确认后测试；没有执行海外生产发布或真实支付开放。
