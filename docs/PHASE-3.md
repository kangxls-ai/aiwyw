# P3 软件授权、表单布局与排序

本阶段延续已确认的永久大版本权益、同大版本更新和整单退积分规则。Windows客服托盘程序仍属V1.1；API完整能力、客服聊天、内容运营与完整V1集成验收尚在后续阶段。

## 界面与列表

后台表单、查询区与编辑弹窗统一左标签、右控件。查询文字框约240px，选择框至多240px，普通编辑文字框至多320px，数字160px，日期范围330px，长图文和上传保留宽工作区；窄屏换行但标签仍在左侧。配置名较长时标签允许换行。Element Plus控件继续使用锁定版本。

应用、标签、文件、用户、交易、个人中心交易与换机申请均在SQL层先按白名单字段排序，再分页。默认创建时间降序，点击其他列先降序，再升序，循环两种方向，相同值按稳定ID排序。操作列不参与排序。版本与积分拆成独立列，版本按文本排序。完整的小型栏目、优惠包和设备清单在浏览器按完整结果排序；金额整数比较不经过浮点数。审计页显示最近100条记录，表头排序只在该明确窗口内进行，不表示已查询全库。

应用的创建时间从最早CREATE审计恢复；无法恢复的旧应用采用升级前已知更新时间近似。旧栏目、优惠包从现有审计取最早已知时间；无依据保留0并显示“历史记录”。新资料记录实际创建时间，编辑、发布、回滚不会重写它。购买名称排序索引取订单快照，不受应用改名影响。业务首页仍按栏目的展示顺序排列，后台表格排序不改变展示配置。

## 使用路径

1. 系统管理 → 配置管理 → 软件授权：设置默认设备数，以及激活、在线验证每小时上限。商品级覆盖和客服审核可从“软件授权与换机”进入。
2. 商品管理 → 软件授权与换机：选择应用并保存设备数。没有覆盖时采用全局默认。修改仅影响下次发布，须重新发布应用。
3. 应用编辑：选择“软件激活”，补齐实际安装包/下载地址、版本、积分和介绍后发布。发布事务冻结授权条款；仅下载、外部资源不签发激活密钥。
4. 用户确认兑换后，购买、积分扣减、授权签发同事务提交；相同已拥有大版本不重复扣分。0积分的软件激活商品仍须登录并领取授权；普通0积分工具继续免登录直接下载。
5. 个人中心 → 我的资源 → 激活授权：主动打开后查看密钥及设备；关闭立即清空本地组件内存，未完成请求的迟到响应不会重新写回。换机原因在同一设备弹窗内填写，不叠加第二个弹窗。只能查看当前用户的有效权益，后台不显示用户密钥。
6. 更换设备：用户选择旧设备提交理由；客服或已完成MFA的管理员审核。通过后旧设备凭据即时失效并释放名额；驳回仍保留设备，可补充重提。不得自审。
7. 全额退积分通过时，订单、在线授权及设备同事务撤销，待审核换机申请取消；账户停用后在线校验拒绝。下架不撤销老订单的有效授权。同一已发布大版本不可切换下载/激活类别，防止老用户失去匹配的交付能力；切换须升大版本。

## 客户端接入约定

所有程序接口使用生产HTTPS，密钥与凭据仅放JSON正文，禁止URL、日志、埋点和错误回显。必须发送`Content-Type: application/json`与`X-AIWYW-Request: 1`。原生客户端不携带浏览器Cookie，程序通过随机密钥/设备凭据认证；这些接口不开放跨站浏览器调用。响应禁止缓存。

`POST /api/license/activate`：

```json
{"key":"购买所得43字符随机密钥","deviceId":"至少32字符的稳定随机安装标识","deviceName":"用户可读设备名","productId":"商品UUID","version":"1.0.0"}
```

返回`bindingId`、`deviceToken`、`majorVersion`、`mode`。安装标识应随机生成、稳定保存在设备安全存储中，勿上传硬件序列号；服务器只保存摘要。相同有效设备重复激活返回相同凭据，不额外占额度。不同设备并发激活受数据库锁约束。重新激活已撤销设备会生成新凭据，仍受剩余额度限制。

`POST /api/license/verify`：

```json
{"bindingId":"绑定UUID","deviceToken":"激活返回的随机凭据","deviceId":"同一安装标识","productId":"商品UUID","version":"1.0.1"}
```

成功返回`valid: true`和检查时间；商品必须一致且版本第一段符合已购大版本。校验依据服务器记录，不相信客户端声明的剩余设备数。客户端应在启动和使用受限功能前校验，运行期间控制请求频率并对429退避。没有离线有效期承诺：网络失败不能当作通过；不得长期缓存一次成功来绕过退款撤权。实际撤权生效取决于客户端下次在线检查并执行结果，平台无法远程删除已下载文件或阻止被篡改客户端。

默认激活上限60次/来源/小时，验证120次/来源与绑定/小时，均可后台修改。来源采用实际连接地址，不信任任意X-Forwarded-For；代理后的来源归并需在正式部署时评估。请求正文不会被本服务写入审计。

MarkDo仓库目前未接入以上接口，本阶段不改其客户端、不宣称现有MarkDo安装包已有平台激活控制。介绍见交付的MARKDO-APPLICATION-INTRO.md；应用编辑页“填入MarkDo介绍”只修改待保存内容，不自动定价、替换安装包或发布。

## 数据模型与人工排查

新增5表，详见[LICENSE-SCHEMA.sql](database/LICENSE-SCHEMA.sql)：`license_policy`保存商品草稿策略，`publication_license_terms`冻结发布条款，`software_license`签发购买授权，`license_device`保存设备和凭据摘要，`license_unbind_request`保留换机审核。所有字段有中文COMMENT；完整组合结构见[IMPLEMENTED-SCHEMA.sql](database/IMPLEMENTED-SCHEMA.sql)。

固定锁序是用户→购买订单→软件授权→设备/申请，与退款保持一致。授权密钥和设备令牌原文采用AES-GCM加密，查找用SHA256；只有256位随机令牌，不使用可猜序列号。不得手改设备数绕过历史条款，不得把REFUNDED或REVOKED改回ACTIVE，不得删除审核来复用请求。退款取消待审申请后不能再批准。

排查先核对purchase_order → publication_license_terms → software_license → license_device → license_unbind_request及finance_audit。先停止写入并成套备份数据库和master.key，再按实际原因处理。没有发布授权条款的旧LICENSE快照会拒绝新购，需正常重新发布，不能从当前配置伪造旧条款。恢复旧程序不自动恢复或覆盖数据库，新增字段/表保留；真实收款继续禁用，模拟授权不得改成真实授权。

## 验证范围

新增服务端场景覆盖发布/购买条款冻结、重复激活、并发设备上限、跨商品/大版本与所有权拒绝、停用和退款撤权、换机驳回/重提/通过、审核权限与自审、CSRF与no-store、排序先于分页及SQL白名单。浏览器流程覆盖紧凑左右布局、降序/升序跨页排序、MarkDo填入草稿、购买授权、设备查看、换机审核及退款后令牌失效。运行结果在本阶段测试报告记录。
