# 鼓励值与个人中心列表

2026-11-06追加规则，以本说明覆盖历史需求中的积分、充值称谓及新订单兑换比例；历史交易仍以原快照为准。

## 鼓励值、捐赠与历史兼容

- 前台、后台、通知展示、下载静态页统一使用“鼓励值”“捐赠”。内部既有数据库表、字段和接口路径（例如 `points_units`、`recharge`、`pricePoints`）保留，避免破坏旧订单、客户端及人工核账依据。
- 新捐赠固定为1元获得10鼓励值，普通捐赠和捐赠档位一致。配置管理展示固定比例，服务端拒绝其他比例。档位按捐赠金额计算鼓励值，不再新增超出比例的赠送量。
- 旧余额不放大、不缩小；已创建订单的金额、比例、鼓励值、有效期与权益快照不变，旧优惠订单仍按原快照核销。首次升级将新订单的默认比例迁移为10，仅执行一次。
- 鼓励值内部仍使用整数百分单位，1鼓励值=100单位。真实收款保持关闭，二维码/付款声明仍属于模拟流程；更换图片不等于开通真实捐赠。
- 历史系统记录保留原文，展示层转换旧称谓；文章作者正文不会被全局替换。文章、教程、FAQ和案例保持公开免费阅读，无兑换订单、鼓励值扣减或下载兑换按钮。

## 每日登录奖励

- 按北京时间（Asia/Shanghai）自然日，每个用户每天首次成功登录或有效会话恢复获得1鼓励值；跨日持续使用页面时恢复会话同样触发。
- 未登录、错误密码、无效会话不发奖；需强制双因素验证的管理员/财务在完成验证后发奖，既有MFA政策不变。
- 奖励永久有效，现金成本为0。`daily_login_reward` 的主键为用户、账本模式、日期，记录对应批次及发放时间；账本使用 `DAILY_LOGIN` 类型。
- 发奖事务依次锁定用户/钱包，检查唯一记录，写领取、批次及流水；并发登录、刷新、重试只发一次，失败整体回滚，不允许人工单改余额绕过流水。
- 人工干预前备份数据库。排查时联查领取记录、`wallet_batch` 与 `wallet_ledger`；不要删除领取行单独重发，也不要重跑升级迁移来改动旧账。

## 查询、分页与操作

- 我的账户：捐赠订单、鼓励值流水、鼓励值有效期、我的资源、退款申请、站内通知；个人资料与安全以摘要列表打开修改对话框，API与客服以服务列表进入对应中心。
- API中心：接口与套餐、我的Key、我的订阅、在线调试、调用记录。套餐通过接口操作打开可查询分页列表；调试先选择有权限的接口，再打开调试对话框，不因查询自动发起收费请求。
- 客服中心：在线咨询/历史、公开留言、我的留言与意见。回复和详情从最后的操作列打开，创建入口位于查询工具栏。
- 业务记录由服务端先按当前用户/游客凭证限制范围，再筛选排序分页；页大小有上限，不拉取整个私有集合交给浏览器截断。个人资料一条摘要及两个服务入口为固定小集合。
- 每个列表提供关键词、适用状态/日期筛选及分页；表格行操作集中在最后一列。默认创建时间降序，支持的表头首次降序、再次升序。切换页签和查询会回到第一页，过时请求不能覆盖新列表。
- API记录使用白名单摘要字段，Key列表不返回令牌或哈希；轮换/创建密钥仍只展示一次完整令牌，权限和归属均在服务端检查。

## 时间与页脚

- 所有给人阅读的时间按北京时间统一为 `yyyy-MM-dd HH:mm:ss`，包括列表、详情、历史版本及静态内容。接口数字时间戳、ISO传输格式、HTML机器可读datetime及搜索引擎结构化数据保持标准格式。
- 日期范围查询仍按整日起止筛选；日期控件展示统一格式，结束日包含当天。API Key到期输入使用北京时间，保存时转换为时间戳。
- 页脚移除联系客服与反馈入口；账户服务页签仍可进入客服。旧已发布静态页面由统一展示层同步处理页脚和时间，无需为此覆盖作者正文。
